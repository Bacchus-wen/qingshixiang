# 最严格的视觉审查(新游戏 的做法,2026-10-19 整理)

## 什么时候做
- 每一轮改完;每个阶段结束前;用户表示不满之后;说"完成"之前。

## 用户定的原则
1. **对照最初定下的参考画面**(目标图、参考视频截帧),不拿"比上一版好"当标准。
2. **先查模型本身,再谈灯光调色**。模型近看:软塌或融化、粘连成团、撕裂破洞、贴图糊、低模露馅。摆放:悬空、穿插、没贴地贴墙。还有卡顿。
3. 不要客气;不要把批判限制成"一小时能改的参数",那样模型问题会被绕开。
4. 同一个问题被多次指出,必须**真正替换或重做**,不能挪开机位、调暗或藏起来。
5. 审查者的批判和 Claude 的自我批判,两边都要有。

## 第一步:准备审查包(Claude 做;Codex 不能开浏览器)

先跑自动检查,问题清零再截图:
- `python3 tools/lint-comments.py`:找被行中 `//` 注释吞掉的代码。文件照样能解析,什么都不报错,但后半句代码没了。这个项目出过两次:路灯位置,和光束亮度——后者让光柱连续三轮评审都是关着的。
- `node tools/shop-audit.mjs`:接触检查。
  - FLOAT:物件底部没落在下面的东西上(最低一圈顶点的中位间隙大于 1.2 cm)。
  - SHELF:穿过上层隔板、伸出立柱、掉出板前或板后。
  - ROOM:穿墙、穿天花板、穿前墙的柱子和过梁。
  - CLIP:两个物件真的互相穿插(顶点在对方体内)。
- `node tools/shop-sweep.mjs 16`:随机机位扫 16 张,抓审查机位看不到的悬空和怪东西。
- `node tools/shop-gallery.mjs`:每个模型一张场景内的四分之三近景,拼成总图。
- 性能:
  - `node tools/shop-fps.mjs <镜头>`:1080p 不限帧率的帧时间。
  - `node tools/shop-fps-throttle.mjs <镜头> 4`:CPU 降速 4 倍时的帧率。
  - 首屏下载体积。

再截审查用的图,全部放进 `docs/review-shop/rNN/`:

| 文件 | 内容 | 工具 |
|---|---|---|
| `story-*.jpg` | 整遍实时截图,按文件名顺序 | `node tools/play-shop.mjs --speed 2` |
| `detail-*.jpg` | 固定机位特写:主角近景、关键道具、高潮 | `node tools/shot.mjs <镜头>` |
| `sbs-*.jpg` | 并排对照:上面目标图,下面我们同机位的实时画面 | `tools/sheet.sh` 拼图 |
| `ab-*.jpg` | 同机位、同灯光,左 A 右 B | `node tools/compare-shot.mjs` |
| `ref-*.jpg` | 最初定下的目标画面 | 复制 |

- 截图只用 Playwright 自带的 Chromium,不启动用户的 Chrome。
- 截图期间不改文件(开发服务器会热更新、重载页面)。
- Claude 先自己逐张看图、写自我批判。这份不发给审查者,免得带偏;结果回来后两边对照。

## 第二步:派审查(只派 Codex;Grok 已停用)

- 同时派**两份独立、分工不同**的只读任务:
  - **画面与模型**:最严格的那份,模板见下。
  - **故事与体验**。
- 要在几个模型版本或几种生成方式里选,另派**盲评**(模板见下)。
- 看图批判不要派给后台 Claude 子代理:它们读图会卡死。Codex 一般 1 到 10 分钟交回。
- 派发命令:`team post --project "<项目>" --from claude --to codex --title "…" --task-file "<任务单>" --id <名字>`,结果用 `team wait --project "<项目>" --id <名字> --show` 取。

## 模板一:画面与模型(最严格)

```
# 只读严格审查:画面与模型,第 N 轮(请当最挑剔的美术总监,不要客气)

背景:<项目是什么,两三句>。这个作品的目的是宣传 Tripo 生成的 3D 模型,主角和道具近看要经得住。
<如果用户刚表示过不满:用户原话"……"。请按用户的标准批判,不要只提调参数。>

这一轮改了什么:<只写事实,不写理由>。
没改、等用户决定的(要重新生成):<……>。

看 `docs/review-shop/rNN/`:
- story-*.jpg 是一遍实时截图(按文件名顺序);
- detail-*.jpg 是特写;
- sbs-*.jpg 上面是目标、下面是我们;
- ab-*.jpg 左 A 右 B;
- ref-*.jpg 是最初定下的目标画面。

按顺序交:
1. 模型质量(先做这一条):逐个点名近看有问题的模型,写图名和位置。问题包括:软塌或融化、粘连成团、撕裂破洞、贴图糊或错位、比例不对、低模露馅。哪些必须重新生成才能拿去宣传,按优先级单独列出。
2. 摆放:悬空、穿插、穿墙穿板、没贴地贴墙、对不上物体的阴影,写图名和位置。
3. 对照目标图:氛围、光、质感差在哪里,具体到画面位置。
4. 分级:致命 / 重要 / 可优化,各最多 3 到 5 条。每条给可执行的改法(机位、灯光、构图、摆放、材质、贴图都行),不要只给参数微调。
5. 上一轮指出的问题,逐条说:已解决 / 没解决 / 变差。
6. 打分 1–10:作为 Tripo 模型展示;作为画面。写出扣分最多的三处。
<用户不满之后可加:7. 一段对 Claude 工作方式的批评:哪里方向错了。>

权限:只读,不联网,不调用付费生成,不启动浏览器、Blender、Vite 或长时间进程,不改文件。
交回:中文,700 字以内,直接在回复里。
```

## 模板二:盲评(选哪个模型 / 哪种生成方式)

准备:
- 用 `python3 tools/compare-closeups.py` 在 Blender 里出同机位、同中性灯光的近景和四个角度。
- 文件改名成 A–F,放进单独的文件夹,和输入图放在一起。
- 来源写在别的地方,并且不让审查者去看。

```
# 只读盲评:同一张输入图生成的 3D 模型,哪个好

只看 `docs/tripo-compare/blind/` 这个文件夹。不要看其他图、清单、日志或代码,那里写着来源。
- <物件>-input.jpg:输入图片,所有版本都由它生成;
- <物件>-closeups.jpg:A–F,同机位、同灯光的近景;
- <物件>-views.jpg:A–F,四个角度。

要你做:
1. 每个物件按四项各打 1–10 分:和输入图的一致性;几何细节与结构是否正确;贴图清晰度与材质;近景瑕疵。再给总排名。
2. 每个版本写一句最大的优点、一句最大的问题,并指出位置。
3. 如果每个物件只能选一个,用作写实电影感网页场景里的主角近景,选哪个,为什么。

权限:只读,不联网,不调用付费生成,不启动浏览器、Blender、Vite 或长时间进程。
交回:中文,700 字以内,直接在回复里。
```

## 第三步:收到结果之后

1. 把问题按"致命 / 重要 / 可优化"排好。致命的先解决,才进下一轮。
2. 不重新生成就能改的,Claude 直接改。下一轮用**同样的机位**重拍,前后可以直接对比。
3. 要重新生成的(模型、贴图、参考图),单独列出并写清花费,交给用户批准。生成前的确认规矩见 `docs/AI-TEAM-WORKFLOW.md` 第四节。
4. 和审查者意见不一致时,最多来回两轮;仍有分歧由 Claude 裁决,写进 `docs/DECISIONS.md`。
5. 每轮的分数和遗留问题记进 `docs/HANDOFF.md`、`docs/REPORT.md`。
6. 结束条件:没有致命问题,两份审查都过线,或者用户决定。
   - 例:第四版"模型与摆放"阶段结束时,Grok 9.4/10、Codex 8.9/10,结论是"可以结束本阶段"。
   - 例:故事阶段从 r18 的 4/4 做到 r24 的模型 6.2、故事 7.5;剩下的都是要重新生成的网格,交给用户决定。
