# 性能记录(Claude,2026-10-16)

测试机:Apple M4 Pro(16 核 GPU),Playwright Chromium,无垂直同步(`--uncap`)。
- 720p:每帧 11–14 ms;1080p:约 20–24 ms;640×360:约 5 ms。
- 空场景 1080p:开后处理 6.6 ms,关后处理 1.0 ms(TRAA+SSR+DOF+泛光约 6 ms)。
- 单独关掉体积雾、SSR、景深、TRAA、雨、人影、所有灯、甚至把材质全换成最简单的,1080p 都在 ~20 ms:没有单一热点,是整体几何/通道的固定开销。
- **运行中切换灯光可见性会让所有材质重编译,卡顿数百毫秒到十几秒——绝对不要做**(本项目已全部改为改强度)。
- 已做:静态网格按材质合并(街道 1182→354 次绘制,机器人 678→300);遮挡层深度预通道(只画大块遮挡物);闭眼时不更新眼睛阴影;资源 8.8→4.0MB。
- 已加:默认 1 倍像素比 + 自适应分辨率(连续 2 秒超过 20.5 ms 就每次降 0.15,最低 0.6)。`?dpr=1.5` 可强制。
- 工具:`node tools/shot.mjs <镜头> --uncap --size 1920x1080`(打印 frameMs)、`node tools/profile.mjs <镜头>`(CPU 剖析)。

## 最终测量(13:10,接上电源后)
之前的数据是在电池电量很低(后来耗尽休眠)时测的,系统很可能在降频。接上电源后同一台 M4 Pro、不锁帧:
- 720p:开场街道 5.5 ms、记忆街道 7.5 ms、门的记忆 6.8 ms(约 130–180 帧)。
- 1080p:记忆街道 15.3 ms(约 65 帧)。
- 打包体积 6.7 MB(首屏预算 15 MB)。
中档笔记本按 GPU 约为这台的 1/3 估算,1080p 约 20–30 帧;自适应分辨率会把内部分辨率降到 0.75–0.6 倍以保持流畅,或直接用 `?q=low`。

## 打开慢、开场卡顿(2026-10-21,用户反馈"打开要 1 分钟,开始阶段非常卡")
测法:`node tools/perf-open.mjs [--url http://127.0.0.1:5181/] [--uncap] [--profile f.cpuprofile]`。用 Playwright 的 Chromium 模拟用户的窗口:1512×890,2 倍屏。按真实时间量,不是按故事时间;记录点击前后每一帧、每次显卡程序编译、每个模型文件。以前的截图工具和 `play-shop` 都按故事时钟等待,所以从来没量出卡顿。

**原因,按影响大小:**
1. **显卡程序在故事里临时编译。**
   - 每种材质第一次进入镜头时,浏览器的显卡进程才编译它,这一帧就停住等。
   - 开场镜头一路扫过店里,编译了约 200 个程序,单帧最长 16.8 秒。
   - 前 45 秒里卡掉 38 秒;剖析显示网页本身的 JavaScript 有 33 秒在空闲等待。
2. **分簇光照(Forward+)。**
   - 它的网格按画面分辨率划分。分辨率一变(自适应分辨率降档、拖窗口),所有材质都要重建、重编译,每次卡几秒。
   - 卡了又被判成"帧慢",于是再降一档,恶性循环,一直降到 0.75 倍。
   - 它的代码还让每个着色器大 2–4 倍:不重复的 WGSL 共 13.7 MB,关掉后 3.3 MB。
   - 修理铺只有 4 盏点光源,用不着它。第三版的雨夜街道有几十盏灯,需要它。
3. **本机预览版加载原始网格(L0)。**
   - 机器人 L0 有 79 MB,带 8K 贴图,超出 600 MB 的显存预算,一次观看里被释放又重载 10 次。
   - 整个故事一共下载 1.15 GB,其中 L0 占 879 MB。
4. **渲染倍数过高。**
   - 默认 1.5 倍,在用户窗口里就是 2268×1335。这个场景卡在显卡填充率上:1.5 倍 20–28 帧,1.25 倍 66–74 帧,1 倍 93 帧(不锁帧)。
   - 每帧的 `submitMs` 里包含了等显卡的时间,不能单凭它判断瓶颈在 CPU。

**改法:**
1. 显卡程序全部异步、并行编译(`threeFixes.js` 的 `asyncPipelines`)。编译完之前,那个物体先不画,帧不等它。
2. 加载画面里预热(`Engine.warmUp`):场景里每个可见物体关掉视锥剔除,在每一个通道里各画一遍(深度预通道、主通道、每张阴影图),等编译完成。约 100 个程序,2–3 秒。
3. 分簇光照只给声明了 `clusteredLights` 的场景用,目前只有第三版街道。`?clustered` 可强制打开做对比。
4. 正式打包版本默认最细只用到 L1,和网页版一致。`?lodmin=0` 可以恢复 L0。
5. 渲染像素上限约 210 万(相当于 1080p,和评审截图同尺寸),且不超过 1.5 倍。窗口变大时自动重算,自适应分辨率只往下调。

**结果**(同一台 M4 Pro、同样的窗口):
- 加载画面 2–6 秒。
- 点击后不再编译任何显卡程序。
- 整个故事稳定 60 帧(垂直同步),只有点击后第一帧 0.12 秒。
- 下载 190 MB,没有 L0,没有重复加载。

**注意:**
- 分簇光照的灯光数据会晚几帧更新,所以以前的评审截图里,工作台那一镜背景墙偏亮(平均 73,实际观看是 37)。
- 现在截图和观看一致。逐盏关灯对比用的是本地探针 `tools/_lightprobe.mjs`(按规则不入库)。

## 近景时材质"闪一下"(2026-10-21 晚,用户反馈)
- **原因:** 模型换级。探针是 `tools/_flashprobe.mjs`(本地,不入库):让光停在几处,镜头飞近时记录每次换级,并连续截图。
  - 镜头一飞近,周围十来件东西在几帧内相继换级;镜头一离开又降回去,电视、热水瓶等来回换了两三次。
  - 每换一次,贴图清晰度都会突然跳一下。
  - 原来的标准按网页逻辑像素计算,还允许贴图先放大到 1.33 倍才换,所以换的那一刻前后差别明显。
  - 显卡程序的异步编译不是原因:探针里缺画 0 次,点击后新建程序 0 个。
- **改法**(`lod.js`):
  - **按实际渲染像素判断,贴图不许被放大。** 细一级在两级还看起来一样时就换上。
  - **换粗要留 2 倍余量,并持续 2 秒。** 镜头飞进飞出时不再来回切换。
  - **换级用 0.35 秒交叉淡入。** 两级同时画,各占一组互补的随机像素,每帧换一组,由 TRAA 平均成平滑过渡。遮罩同时作用在阴影上。
  - 评审截图关掉淡入(`ctx.isShot`),并且不加遮罩;`?nolodfade` 也可以关掉。
- **结果:**
  - 近景里只剩"换细",不再来回切换。
  - 强制机器人在两级之间来回切,截下的帧完全一样,没有洞、重影或噪点。
  - 代价:每帧多 0.4–0.8 毫秒(交替 A/B,不锁帧)。进店后约 69 对 71 帧,街景约 87 对 92 帧,仍远在 60 帧以内。
