# 项目需求说明(可直接转述给 AI)

> 你是一名资深 WebGPU/three.js 图形工程师兼技术美术。请按下面的需求,从零实现一个浏览器 3D 项目。
> 参考来源有两个,只学思路、不复制代码和素材,因为参考仓库没有开源许可:
> - A. xikhar 的 cybercity(NEON KAIDO):用 three.js 和 WebGPU 做的雨夜霓虹日式街区,强在氛围系统。
> - B. thtbee_ 的 KESTREL K-1 人形机器人展示:强在可检视的精细机械模型和交互。
> 目标是把 A 的"可漫游世界和氛围"与 B 的"可拆解、可检视的主角机体"融合起来,但视觉风格和完成度都要做出区别,不是照抄。

## 0. 项目定位(请先确认,不确定就用默认值)
- 名称:暂定「HARBOR UNIT」(可改)。
- 一句话:在一座黄昏起雾的未来港口城市里,玩家操控或跟随一台模块化机体,随时可以进入"检视模式",对机体进行爆炸拆解、透视和换装。
- 风格差异(默认):A 是雨夜霓虹,B 是白色影棚。本项目用 **黄昏到夜晚的雾港**,主色是暖橙天光配冷青工业灯,整体走"工业写实加少量科幻",霓虹只做点缀,不铺满。
- 完成度分级:先做 MVP(第 10 节第一阶段),再逐级加特性。每个特性都要能用开关关掉,同时做低、中、高三档画质。

## 1. 技术栈
- three.js 最新版,用 `WebGPURenderer`,不支持时自动退回 WebGL2,并在控制台提示。
- 着色器用 TSL(three.js 的节点着色语言),后处理用 three 自带的 TSL 节点(bloom、SSR、TRAA 等)。
- 物理用 Rapier(`@dimforge/rapier3d-compat`),打包用 Vite,用原生 ES 模块,先不用 React。
- 动画用 GSAP 做镜头和 UI 过渡。
- 所有模型用 glb 格式,纹理尽量用 KTX2 压缩,不要像参考项目那样放十几 MB 的 PNG。

## 2. 代码架构(学 A 的做法)
按系统拆目录,每个系统都有 `init(engine)`、`update(dt)`、`dispose()`,并能单独开关:
```
src/
  engine/   Engine.js(渲染器、主循环)  PostFX.js  Assets.js  Input.js  Quality.js
  materials/  wet.js  noise.js  emissive.js
  systems/
    world/       城市布局、建筑、道具(程序化加模块化)
    ground/      路面、标线、贴花、积水
    atmosphere/  天空、雾、体积光
    weather/     雨、溅水、蒸汽、闪电、天气切换
    crowd/       人群(VAT)
    vehicles/    交通(LOD 加车道路径)
    mech/        主角机体:组装、骨骼挂载、动画、IK
    inspect/     检视模式:爆炸视图、透视、标注、镜头
    audio/       程序合成音景
    player/      控制器、镜头、任务
  ui/       hud  minimap  inspectPanel  menus
  world/layout.js   用一个种子数控制整个城市生成
```
- 所有随机都走同一个带种子的随机数生成器,保证同一个种子生成同一座城。
- 做一个调试面板(用 lil-gui),能实时调画质、天气、时间、各系统开关。

## 3. 渲染和后处理(核心在 A,要改出自己的风格)
后处理管线按这个顺序:
1. 场景渲染(MRT 多目标输出:颜色、法线、粗糙度、速度)。
2. **SSR 屏幕空间反射**:半分辨率,只给"光滑的湿表面"反射。反射强度由粗糙度和湿润度驱动,而不是金属度。竖直墙面不做 SSR(容易糊),粗糙表面交给环境贴图。
3. **湿地面竖向拉伸**:对反射结果做竖向模糊,模拟灯光在湿路上的竖条倒影。
4. **Bloom**:只让自发光和高亮部分泛光,强度适中,不要糊成一片。
5. **TRAA 时间抗锯齿**。透明物体(雨、雾、光晕)不能写入 G-buffer,否则 SSR 和 TRAA 会出错(参考项目专门处理过这一点)。
6. **色调映射**:用 AgX,曝光可调。
7. 风格化收尾:轻微的色差、颗粒、暗角。色差强度要比 A 弱很多,A 的色差太重。
8. 加一层 LUT 调色,做出"暖橙对冷青"的雾港色调,并提供 2 到 3 个 LUT 切换。

## 4. 材质
- **湿润系统**(学 A 的 `wet.js`):全局湿润度 uniform(0 到 1),包含积水遮罩(用噪声加地面低洼)、雨滴涟漪法线、湿润时变暗变光滑。要修掉 A 的问题:A 的倒影太像镜子,所以积水区要叠涟漪法线扰动,非积水区要保留粗糙度。
- **机体材质**(学 B):做 PBR 材质预设,包括亮面陶瓷白、深色拉丝金属、哑光碳纤维、透明玻璃或亚克力、内部自发光线路。每套配色主题(至少 3 套)要同时切换外壳颜色、自发光颜色和背景氛围。
- **自发光**:单独一套 emissive 材质,支持呼吸和闪烁,灯牌偶尔"接触不良"地闪一下。

## 5. 世界和氛围(学 A,风格改成雾港)
- 城市:码头、集装箱堆场、起重机、仓库、窄巷、高架路、一条运河。建筑用"模块化组件加程序化拼装",用贴图集减少绘制调用,大量重复物件用 `InstancedMesh`。
- **橱窗或室内**:不要用 A 那种平面贴图。用 interior mapping(视差室内着色器),让窗户里有假的纵深。
- 招牌:用贴图集加合批渲染,数量和密度可调,并加入随机变化(颜色、文字、破损),避免 A 的重复感。
- 大气:高度雾、体积光柱(从路灯和起重机灯打下来)、远景天际线剪影、可以从黄昏到夜晚变化的天空。
- 天气:晴、雾、小雨、大雨四档平滑过渡。雨用 GPU 粒子,包括近景雨丝、远景雨幕、地面溅水、屋檐滴水、井盖蒸汽、闪电(闪电同时照亮场景并触发雷声延迟)。镜头雨滴可以做,但默认关闭。

## 6. 人群和交通(学 A,修掉 A 的 bug)
- 人群:用 VAT(把骨骼动画烘焙进贴图,GPU 实例化播放)支持几百人。走路、站立、打伞几种状态,服装和发型随机组合,在人行道上沿导航线走。
- 交通:车道用样条路径,车按路径行驶并带跟车距离判断,禁止互相穿模。车辆不要用自由刚体乱撞,用"运动学加路径"驱动,只在发生碰撞时才交给物理。这是为了修掉 A 里车辆飞天和悬空的 bug。
- 每种车做 3 到 4 级 LOD,远处用最简模型。生成和消失都放在视野外或雾里,避免 A 那种突然冒出来。
- 车型至少 8 种,并加颜色和贴花随机,避免 A 只有 5 种车的重复感。

## 7. 主角机体(融合 B 的核心,用 Tripo 降低建模成本)
- **模型来源**:用 Tripo 按部件分开生成(头、胸甲、背包、上臂、前臂、手、大腿、小腿、脚、武器),不要整体生成。在 Blender 里统一比例和轴心点,去掉烘焙在贴图里的光影,重新套 PBR 材质,减面到合适的面数。
- **零件刚性挂骨骼**(学 ShadeLurk 的机甲做法):零件不做蒙皮,直接挂到对应骨骼上。好处是金属不会被拉伸,能掩盖 AI 模型拓扑差的问题,而且零件可以随时换。
- 零件做成插槽系统:`slot`(头、核心、手臂、腿、武器)加 `partId`,用一份 JSON 描述每个零件的挂点、偏移、属性(重量、能耗等)。
- 动画:待机呼吸、走、跑、挥手、检视姿势。上半身用瞄准 IK,头部跟随鼠标或目标。
- **脚步落地**:做 foot IK 加脚步锁定,保证移动速度和步幅对齐。A、B 两个参考和 ShadeLurk 的机甲都有脚底打滑的问题,这是本项目必须做好的点。
- 手部可以做几种预设手势(握、捏、指),用简单的姿势混合实现。

## 8. 检视模式(学 B,作为本项目的亮点)
- 按一个键或点 UI 进入检视:时间放慢,背景虚化变暗(景深加压暗),机体移到画面中央。
- **爆炸视图**:用滑块控制,所有零件沿各自的"爆炸方向"向外散开(在零件 JSON 里定义方向和距离),要有缓动。
- **跟随标注**:标注线和文字必须跟着零件的 3D 坐标走,把 3D 位置投影到屏幕上每帧更新,被遮挡时自动淡出。这是为了修掉马车网站那种标注线乱指的问题。
- 视图模式:影棚(干净灯光)、玻璃透视(外壳变透明,露出发光骨架)、信号(线路高亮流动)、热成像(按部件"温度"上色)。
- 镜头:点击部位(头、胸、手、背包),用 GSAP 平滑飞过去对准,然后可以围绕该点旋转,再点"复位"平滑回去。
- 换装:在检视面板里切换零件,新零件从上方落下吸附到骨骼位置,主体在换装时短暂变成蓝色全息(学 ShadeLurk 的组装界面)。属性条(重量、能耗、装甲)实时变化。

## 9. UI 和声音
- **游戏 HUD**(学 A,但更克制):左上状态,右上小地图加时间和天气,右侧任务追踪。字体是标题用一款有性格的无衬线字体,数据用等宽字体。
- **检视 UI**(学 B):工程图和 CAD 风格,用细线框、模拟实时数据曲线(功率、温度、能量)。
- 所有 UI 用 HTML 和 CSS 叠在画布上,要做响应式,支持键盘操作。
- **声音**(学 A,程序合成):雨声分近远两层、排水、港口汽笛、起重机金属声、远处车流、霓虹嗡嗡声、雷声、机体脚步和关节伺服声、检视模式的 UI 音效。用 Web Audio,音量随距离和天气变化。

## 10. 分阶段交付(每一阶段都要能跑、能演示)
1. **第一阶段 MVP**:引擎骨架、画质分级、一条街区、湿地面、基础后处理(bloom、色调映射),以及主角机体的组装、挂骨骼、待机和行走,加上镜头跟随。
2. **第二阶段**:SSR 湿反射、雾和体积光、天气四档、闪电,加上检视模式(爆炸视图、跟随标注、镜头飞行)。
3. **第三阶段**:人群 VAT、交通、招牌系统、程序音景、小地图和任务。
4. **第四阶段**:换装、配色主题、玻璃透视、信号和热成像视图、LUT,以及性能优化。

## 11. 性能目标
- 中档画质在主流笔记本上稳定 60 帧,低档能跑在集显上。
- 首屏加载控制在 15MB 以内,其余资源按需流式加载。
- 用 `renderer.info` 做一个性能面板,显示绘制调用、三角面数、显存。

## 12. 必须避开的已知问题(来自参考项目的短板)
1. 车辆穿模、飞天、悬空:用路径驱动加碰撞检测。
2. 车型、行人、招牌重复感强:增加种类和随机变化。
3. 远处物体突然出现:在视野外生成,用雾遮挡,LOD 渐变。
4. 橱窗内部是平面贴图:改用视差室内着色器。
5. 倒影太像镜子:积水叠涟漪,非积水保留粗糙度。
6. 色差太重:降低强度。
7. 脚底打滑:foot IK 加步幅同步。
8. 标注线不跟随模型:3D 投影跟随。
9. 地面阴影是静态的:用实时阴影或动态接触阴影。
10. 特效风格不统一:所有特效走同一套写实偏风格化的规范。
11. AI 模型的光影烘焙在贴图里:导入前在 Blender 里清掉,重新套 PBR。
12. 纹理太大:用 KTX2 压缩加贴图集,控制尺寸。
