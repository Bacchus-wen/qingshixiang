# 概念补充:雨夜废城 + 残破机器人 + 记忆投影

## 1. 核心一句话
一座被遗弃的雨夜城市里,一台残破的机器人在原地坐了很多年。玩家让它残破的机械眼缓缓睁开,眼里的光投射出它记得的过去:同一条街,曾经人来人往、霓虹满街。

## 2. 关键想法:让两个参考变成"过去",废墟是"现在"
- A(霓虹街区)不再是要复刻的风格,而是**记忆里的城市**:热闹、拥挤、灯火通明。
- B(白色精密机器人)不再是要复刻的展示,而是**机器人记忆里的自己**:完好、干净、崭新。
- 现在的画面是两者的反面:城市空了,灯灭了;机体坏了,锈了。
- 这样两个参考就从"抄谁的风格"变成"叙事上的对照",差异化自然成立。

## 3. 情绪曲线(一次完整体验约 3 到 8 分钟)
1. **寂静**:只有雨声。镜头在废街里缓慢推进,几乎没有光源。
2. **发现**:机器人靠墙坐着,半边身体浸在积水里,看不出是否还"活着"。
3. **唤醒**:玩家靠近或长按,机器人内部有微弱的伺服声,眼睛闪了一下又灭了。
4. **睁眼**:第二次尝试,眼睛的光圈叶片卡顿着打开,镜片有裂纹,光束穿过雨幕。
5. **记忆**:光束照到哪里,哪里就显出过去的样子。人群、车流、霓虹,只在光锥里存在。
6. **衰减**:电量不足,记忆开始失真、掉帧、缺块。最后一段记忆最清晰,然后光熄灭。
7. **余韵**:回到废墟。也许留下一个细节变化(一盏灯被点亮、一把伞被放到它手边)。

## 4. 核心交互:"光锥即记忆"
最有辨识度的做法:**投影不是在墙上放电影,而是光锥范围内的世界变回过去。**
- 现在和过去用同一个城市布局(同一个种子),所以过去的招牌、车、人都对得上现在的废墟位置。
- 光锥内渲染"过去",光锥外渲染"现在",边缘有全息式的扫描线和噪点溶解。
- 玩家通过控制机器人的视线(头部转动、眼睛对焦)决定看向哪里,等于用手电筒去照记忆。
- 雨滴穿过光锥时被照亮,像投影屏幕上的像素,这是天然的体积感。

## 5. 睁眼这个动作要做足的细节
- **长按而不是单击**:按住时眼睛慢慢打开,松手会退回去。打开需要"用力"。
- **失败一次**:第一次一定打不开,只闪一下。让玩家意识到它很虚弱。
- **机械结构**:光圈叶片逐片打开,其中一片卡住或缺失;镜片有裂纹,光从裂纹处散射。
- **对焦过程**:画面先模糊,再拉焦清晰(景深从近到远),伴随伺服的嗡声。
- **声音**:齿轮摩擦、电容充电的高频声、电流杂音,打开的瞬间雨声突然变小。
- **代价**:每次睁眼都消耗所剩不多的电量,UI 上能看到电量一格一格掉。

## 6. "荒凉和绝境"靠哪些细节堆出来
原则:荒凉不是"什么都没有",而是"到处都是人曾经在的痕迹,但人不在了"。

**环境**
- 霓虹招牌大多熄灭,只剩一个字在接触不良地闪,发出嗡嗡声。
- 自动售货机是整条街唯一还亮着的东西,里面的饮料褪了色。
- 卷帘门半拉着,门缝里能看到倒下的椅子和没收的碗筷。
- 路面积水很深,漂着传单和一把翻过来的伞;水面有一层油膜。
- 车停在路中间,车门开着,车窗上有青苔,轮胎瘪了。
- 断掉的电线垂到积水里,偶尔打出火花,照亮一瞬间。
- 墙上的海报被雨泡得卷边,寻人启事一层盖一层。
- 植物从裂缝里长出来,藤蔓爬上红绿灯;红绿灯还在徒劳地变色。
- 远处有一栋楼只剩一扇窗亮着,始终不知道里面是谁。

**声音(荒凉主要靠听觉)**
- 只有雨声、滴水声、风穿过破窗的呼啸。没有车流,没有人声。
- 一台坏掉的收音机在某个角落循环播放一句断断续续的广播。
- 唯一的规律声音是红绿灯的提示音,对着空无一人的路口响。

**光**
- 和参考 A 相反:A 有几百个光源,这里只有个位数。大部分画面是暗的。
- 机器人的眼睛是全场最重要的光源,睁眼前后的亮度落差就是情绪落差。
- 偶尔的闪电是唯一能看清全貌的时刻,玩家会在闪电里看到之前没注意的东西。

## 7. 机器人的残破细节
- 一条手臂缺失,断口露出线缆和液压管,雨水顺着线缆滴下。
- 外壳(B 那种白色陶瓷质感)大面积开裂、剥落,露出锈蚀的骨架。
- 一只眼睛彻底坏死,另一只就是能打开的那只。
- 胸口的状态灯极慢地呼吸,说明它还没彻底断电。
- 身上积了水和落叶,肩上可能停着一只鸟或者趴着一只猫(它在这里很久了)。
- 动作:关节卡顿、颤抖,抬头需要好几秒,中途会停下来。
- 记忆里它是完好的,所以记忆投影中的它会和现实中的它形成对比。

## 8. 可以接上参考 B 的检视模式,但改成"损伤检视"
- 爆炸视图里,缺失的零件用半透明的虚线轮廓显示"它原本的样子"。
- 热成像:大部分部件是冷的,只有核心和眼睛还是暖的。
- 标注不写参数,写状态:"左臂:缺失""主电源:3%""记忆模块:部分损坏"。

## 9. "光锥即记忆"的技术实现
三种做法,推荐第 3 种:
1. **墙上投视频**:最简单,但就是放电影,没有空间感。不推荐。
2. **渲染两个完整场景再按光锥合成**:效果最完整,但渲染量翻倍,中低档机器扛不住。
3. **双状态材质 + 光锥判定(推荐)**:只渲染一个场景,每个物体都带"现在"和"过去"两套状态,着色器判断像素是否在光锥里再决定显示哪套。
   - 光锥判定:`inCone = smoothstep(cos(角度+边缘), cos(角度), dot(normalize(像素世界坐标 - 眼睛位置), 眼睛朝向))`,再乘距离衰减。
   - 招牌:光锥外是灭的,光锥内亮起来、颜色鲜艳。
   - 卷帘门、车、植物:光锥内门升起、车完好、植物消失。
   - 只存在于过去的东西(行人、行驶的车):做成全息体(半透明、扫描线、轻微抖动),只在光锥内可见。人群可以复用 VAT 思路,但数量少得多。
   - 雨粒子用同一个判定:进入光锥的雨滴变亮、染成记忆的颜色,像投影的像素。
   - 光束本身:锥形网格加噪声和菲涅尔,叠加混合,不写入 G-buffer(参考 A 的处理)。
- 记忆失真:电量越低,光锥边缘越破碎,用噪声阈值让过去的画面出现缺块和错位。
- 睁眼动画:用 GSAP 时间线驱动几个 uniform(光圈开合、对焦距离、电量、光锥角度),光圈叶片是独立的小零件。

## 10. 和 fusion-prompt.md 相比的取舍
新方向把开放世界缩到**一条街加一个路口**,反而更容易把细节密度做上去。
- **删掉或降级**:交通系统(只剩静止的废车)、大规模人群(只在记忆里出现)、任务、小地图、游戏 HUD、换装、配色主题。
- **保留**:湿润系统、雨、SSR 湿反射、雾和体积光、程序音景(重要性上升)、机体零件化(用于损伤和爆炸视图)。
- **新增**:`systems/memory/`(光锥、双状态材质、全息体)、`systems/robot/eye`(眼睛装置和睁眼时序)、记忆片段数据(每段记忆对应哪些物体、什么时长、什么声音)。

## 11. 建议的阶段
1. 废街白模、雨、湿地面、个位数光源、机器人占位模型静坐。先把"荒凉"的基调做出来。
2. 睁眼交互:长按、失败一次、光圈、对焦、光束、雨滴受光。
3. 光锥记忆:招牌和卷帘门的双状态、全息行人和车。
4. 记忆衰减、声音设计、结尾。
5. 损伤检视(爆炸视图、缺失零件轮廓、状态标注)。

## 12. 需要你决定的问题
1. **玩家是谁**:a) 路过的人或无人机,唤醒这台机器人;b) 玩家就是这台机器人;c) 不设角色,只用镜头加交互讲故事。MVP 建议 c 或 a。
2. **记忆怎么触发**:固定顺序播放几段,还是光照到特定物体(一把伞、一个招牌)时触发对应的记忆?建议后者。
3. **结局**:机器人最终熄灭,还是留下一点希望?
4. **形式和时长**:3 到 8 分钟的网页短体验,还是可以反复探索的小场景?
5. **是否商用**:决定能否改编参考 B 的模型(CC BY-NC 4.0 只允许非商业使用)。
