# 第四版:老街修理铺 —— Tripo 模型展示(规划,等用户确认后开工)

## 为什么换场景(2026-10-18 用户决定)
- 作品目的:**宣传 Tripo 生成的 3D 模型**。旧场景(84 米雨夜长街)太暗、太大、主角太远,恰好把模型质量藏起来,显存还用到 1.23 GB。
- 新场景:**拆迁区里一间关了门的家电修理铺**。小空间、暖光,8–12 件 Tripo 主角模型全部能近看;故事核心(机器人的眼睛照出过去、门框上的身高刻度)保留。详细设计见 `docs/scene-shop.md`。

## 第三版的教训(自我批判,保留)
1. 方向错:把时间花在灯光后期,模型没做好。
2. 主角不是 Tripo、不合格的模型被藏起来而不是换掉。
3. 没有验收标准:没查贴地贴墙、没对照参考、只在 M4 Pro 上看帧率。
4. 批判被带偏到"一小时能改的参数"。

## 方法:参考图驱动 + 并排对照循环
参考作品的作者(cybercity 用 Opus 5.5 + Blender)都是同一个方法:**先有一张好的参考图,再让一个苛刻的视觉代理把实时画面和参考图并排盲比,一轮轮改**(见 `.agent-tasks/r22-posts/result.md`)。我们照做:
1. 你用 Midjourney 出关键画面(`docs/scene-shop.md` 的 S1–S4),选定一张作为**标准画面**。
2. 每个主角模型:按标准画面的风格写建模参考图提示词 → 你出图 → 我挑图、报 Tripo 参数与积分 → 你确认 → Tripo 生成 → Blender 无界面渲染原件四个角度存档。
3. 每完成一步,用同一机位截图,和标准画面并排;Claude 助手、Codex、Grok(精简任务)和我自己各写批判,按"对宣传 Tripo 的影响"排序修改。

## 验收标准(先定标准再动手)
- **模型**:每件主角模型的近景截图与参考图、Tripo 原件渲染并排,经得住看;减面后轮廓不坏。
- **零悬空零穿插**:自动检查工具(`tools/audit-contact.mjs`)所有物体离地、离墙、离桌面不超过 1 厘米,并有支撑关系。
- **流畅**:显存 + 内存总预算约 400 MB;默认内部渲染约 1280×720;普通集显笔记本冷启动完整跑一遍,记录峰值内存与 P95 帧时间;下载包 30 MB 以内。
- **画面**:每轮与标准画面并排比较,而不是和上一版比较。

## 技术预算(小空间可以做得又好又轻)
- 主角模型:机器人 5–8 万面、2K 贴图;其他主角 1–2.5 万面、1K 贴图;小物件 3–8 千面、512 贴图;全部 KTX2 压缩。
- 房间:简单几何 + 高质量贴图(地面水磨石、墙面旧涂料与瓷砖腰线、天花板);可在 Blender 里烘焙环境光遮蔽。
- 光:台灯暖光、门外黄昏天光、一根日光灯;记忆里电视屏幕、霓虹招牌、店里全部灯亮。动态光不超过 8 盏。
- 后期:抗锯齿、低分辨率泛光、轻量调色、半分辨率 AO;不再用全屏景深、SSR、散射拉丝等重效果。

## 执行顺序(开工后约 10 小时)
| 时段 | 内容 |
|---|---|
| 0–1 h | 你出关键画面;我搭新场景骨架(房间灰模、机位、灯光基础、轻量渲染管线、性能计量) |
| 1–3 h | 主角模型参考图(你出)→ Tripo 生成(机器人、工作台+台灯、电子管收音机、电视机、电风扇、挂钟、铁皮玩具机器人、门与门框……) |
| 3–6 h | 模型处理与接入(减面、KTX2、摆放贴地)、灯光、记忆状态(电视亮、风扇转、钟摆动、收音机响) |
| 6–8 h | 故事流程(门外进入 → 唤醒 → 环视 → 门框刻度 → 结尾)、声音 |
| 8–10 h | 两轮并排批判与修改;弱设备实测;文档与冻结 |
