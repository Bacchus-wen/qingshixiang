# 只读评审:第一幕到第二幕的故障转场(全新评委,请苛刻)

背景:新游戏 是一段 three.js WebGPU 网页实时体验,目的是宣传 Tripo 生成的 3D 模型,同时要打动人。故事:拆迁区一间关了门的家电修理铺,黄昏;店里的旧物和小机器人都是 Tripo 生成的原始网格。机器人睁眼,光照到哪里,哪里就回到从前,它的眼睛像一台记忆投影机。

第一幕在店里,机器人背对店门、面朝工作台。第一幕结尾,街对面传来同一支曲子,第二幕里它要面朝街。
- 原来是让它在凳子上转过身,但用户否决了:动画化的转身把钢铁身体拉伸变形了。
- 用户要求"直接故障特效转场",即不演转身,用画面故障盖过去。

现在的做法(从门口看它的背影,镜头缓慢前推):
- 0–0.6 秒:它静止,在听。
- 0.62 秒:一次小故障,强度 0.35,持续 70 毫秒。
- 1.02 秒:又一次,强度 0.5,持续 100 毫秒。
- 1.37–1.65 秒:画面撕裂,强度升到 1。
- 1.65 秒,在最强的一帧剪切到第二幕:机位在它身后,它已经面朝街道,眼睛的光束照到对街。
- 之后 0.6 秒故障退去,中间在 0.32 秒处再抽动一下。
- 效果构成:水平条带左右错位、零星方块显示成别处的画面、红绿蓝通道错开、扫描线、雪花带、整帧明暗跳动。
- 声音:合成的跳频方波短鸣,加高通噪声的断续爆音。

要回答的:
1. 这个转场能不能让观众理解"它转过来了,现在面朝街"?会不会被看成程序出错或画面坏了?
2. 风格是否契合"机器人的记忆投影 / 老电视、收音机"这个世界?数字感(色彩偏移、马赛克坏块)和模拟感(扫描线、雪花、行不同步)的比例是否合适,该往哪边偏?
3. 节奏:两次预兆、撕裂的长度、剪切点、退去的长度,各自应该怎么改,给出具体秒数。
4. 画面上的具体问题,比如雪花带太亮太整齐、条带的宽度和位移量、坏块的大小。逐条写清是哪里、为什么不对、改成什么参数。

交回格式:第一行写 `总评 X/10`,然后是按影响排序的问题清单,每条都要给出可执行的改法。中文,900 字以内,直接在回复里。

权限:只读,不联网,不调用付费生成,不启动浏览器、Blender、Vite 或长时间进程,不改文件。
