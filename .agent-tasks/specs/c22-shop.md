# 只读批判：修理铺场景（模型 + 摆放阶段）

## 背景
项目 新游戏（three.js 0.186 WebGPU + TSL，Vite）。场景已从"雨夜街道"换成室内：1990 年代中国老街家电修理铺，黄昏，写实电影感。主角是老师傅用旧家电拼成的小机器人（收音机外壳头 + 相机镜头眼 + 钣金机身带风扇 + 水管四肢）。整个项目的目的：**展示 Tripo 生成的 3D 模型质量**——模型近看要经得起看、摆放要真实（不悬空、不穿插）、页面要轻、别人的设备上也要流畅。当前阶段只做"模型 + 场景摆放"，灯光/调色/后期以后再做。Tripo API 余额已用完，不能再生成新模型。

## 要你做什么
1. 读代码：`src/systems/shop/index.js`（场景、材质、摆放与"下落检测"落地）、`tools/shop_layout.py`（布局生成）、`tools/shop-audit.mjs`（接触审计）、`src/engine/shots.js`（机位）。
2. 看图（能看图就看；不能看就只评代码）：`docs/review-shop/r02/` 下的 `sbs-establish.jpg`（左=目标关键帧，右=我们的实时渲染）、`sbs-robot.jpg`（左=机器人设计图，右=场景里的机器人）、`sbs-layout.jpg`、`shop-left.jpg`、`shop-back.jpg`、`shop-bench.jpg`、`shop-front.jpg`。
3. 找问题，按"致命 / 重要 / 可优化"三级列出，每条给证据（文件:行号，或图片位置）和具体修法。重点：
   - 摆放逻辑会不会让物体悬空、穿插、穿墙（下落检测的漏洞、货架层高、贴墙逻辑）；
   - 性能：draw call、三角形数（当前约 120 万三角、470 次 draw call）、贴图显存、运行时射线检测的开销、可合并/实例化的地方；
   - 画面上明显假、重复、空的地方，和目标图比差在哪；
   - 只能用现有模型（列表见 `assets/models/shop/`）、程序几何、贴花和材质来修，不能生成新模型。
