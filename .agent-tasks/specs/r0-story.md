# 任务:剧情方案 + 核心技术风险审查(只读)

## 背景
项目 新游戏(先读项目根目录下的 AGENTS.md 和 docs/concept-ruin.md)是 3 到 8 分钟的网页短体验:荒凉的雨夜废城 + 一台残破的机器人,玩家长按让它的机械眼睁开,光锥照到的地方显出城市的过去。非商用。three.js 0.186.1 WebGPURenderer + TSL。用户把剧情交给 AI 团队决定,要求有情感力量、不落俗套。

## 要做什么
A. 剧情:
1. 写 3 个互相不同的剧情方案,每个包括:机器人是谁、玩家是谁(可以不设角色)、城市为什么荒废(可以留白,但要有暗示)、5 到 7 段记忆片段(每段:由废墟里哪个具体物体触发、记忆里看到什么、时长、情绪)、结尾。
2. 避开俗套:不要"人类灭绝因为 AI 叛乱",不要大段旁白或字幕说教。尽量用画面、声音和交互讲故事,文字只用于极少量的标签或残缺信息。
3. 推荐一个并说明理由。

B. 技术风险审查(核心交互):方案是"单场景 + 双状态材质":每个材质用 TSL 判断像素世界坐标是否在眼睛的光锥里(dot(normalize(P - eye), dir) 与 cos(angle) 比较),光锥内显示"过去"状态(招牌亮起、卷帘门升起、全息行人),光锥外显示"现在"的废墟。列出 three.js r186 WebGPU/TSL 下的 3 到 6 个具体风险(性能、几何体在两种状态下形状不同怎么办、阴影和光照、透明排序、WebGL2 回退等)和对应的解决办法。
